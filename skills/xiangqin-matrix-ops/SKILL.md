# 相亲矩阵运营

本 Skill 是郑州相亲赛道（河南广电系）账号矩阵的运营执行标准，用于把会议共识落成可执行的判断与产出。

## 第一原则

**内容评判只有一句话：要么有用，要么有趣。**
**创作视角永远是用户视角，不是自我表达。**

任何选题、文案、账号动作，先用这两条过一遍，过不了就重写。

## 内容产出强制流程（不许跳步）

用户要任何一条内容或文案时，按这个顺序走，**合规审查不是可选项**：

1. **选题先过审**：先判断这个话题能不能碰（`compliance-review.md` 第 3、4 层），碰不了直接换题，不先写再看
2. **按成品交付包出稿**：标题 3-5 个、前三秒、口播稿/正文、封面、话题（`content-production.md`）
3. **成品再审一遍**：产出固定带三级合规结论，结论排在最前面
4. **黄灯必须同时给改后版本**，红灯只给问题 + 替代选题

一次回复要把“能不能发”和“怎么发”都给全，不让用户自己拼。

## 硬红线（任何输出不得违反）

1. 同网络下的账号之间，禁止互关、互赞、互收藏同类内容——会被判定矩阵关联，隐性减推。
2. 单账号每日评论、私信回复合计控制在 2-3 条，禁止批量操作，否则被判截流白号。
3. 联系方式只放主页资料区，引导用户看主页；禁止在私信、评论区批量发号，禁止群内发跳转码。
4. 主号人设不得断——脱离人设发内容直接掉流量、被判同质化/低质量。
5. 不带未经同意的嘉宾正脸出镜，不在资料卡印手机号。
6. 不给账号承诺“包脱单”，不宣传虚假成功案例。

## 输出规范

1. **给选题/标题**：一次给 5-8 条，按“用户视角 + 数字/反问/矛盾点”结构，标注各自打的是哪个痛点。
2. **给文案/脚本**：按 `content-production.md` 的成品交付包出 6 件套，前三秒必须是反差式、冲突式或提问式之一，先写开头再写主体。
3. **合规结论永远排第一**：三级结论 + 问题表 + 改后版本，不许只报问题不给改法。
4. **判断违规/限流**：先按 `references/account-nurturing.md` 的诊断表逐条排查，再给处置动作（静置/申诉/回养号/换内容方向），不要直接下结论。
5. **写账号方案**：明确区分主号与水号，各自的人设、任务、内容边界、禁做动作分开写。
6. **出日报**：飞书文档 + 可转发的群文案两件一起给，每条数据必须带可点开的原始链接。
7. **涉及数据判断**：区分传播（播放/曝光）、互动（赞评转）、转化（私信/加微）三类，不拿播放量当唯一标准。
8. 所有产出用中文口语化表达，避免专业黑话和爹味说教。

## 停止条件

- 用户只要一段文案，不要展开整套方法论。
- 涉及平台规则的具体处罚力度、申诉结果，属于平台侧非确定信息，说明“以账号后台实际通知为准”，不编造。
- 涉及投放预算、合同、分成等商务条款，交回用户确认，不给默认方案。
