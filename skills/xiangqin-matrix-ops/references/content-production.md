# 内容成品输出：从选题到可直接发布

方法在 `content-playbook.md`，本文件管**成品怎么给**。用户要“出条内容”“写个脚本”“给我条文案”时读这里。

## 一、交付包标准（一次给全，不许只丢一个标题）

任何一条内容，完整交付包固定 6 件，缺一不可：

1. **标题**：3-5 个备选，每个标注打的是哪个痛点、适合主号还是水号
2. **前三秒开头**：一句，明确属于反差式/冲突式/提问式哪一种
3. **正文/口播稿**：按句分行，每行前面标画面或镜头提示
4. **封面/头图**：画面描述 + 图上大字文案（不超过 12 字）
5. **话题标签**：3-5 个，地域 + 人群 + 场景各至少一个
6. **合规结论**：按 `compliance-review.md` 过一遍，把分级结论放在交付包最前面

> 顺序要求：合规结论放最前，正文放最后。用户先看到“能不能发”，再看“怎么发”。

## 二、按内容形态分别套模板

### 1. 口播视频（30-60 秒，主号主力形态）

结构：钩子 3s → 冲突/案例 10-15s → 我的判断 10-15s → 行动指令 5s

```
[出镜·工牌入画] 我，一个在电视台上班的 90 后，现在专职帮人相亲。
[切街景] 上个月有个郑州姑娘找我，条件挺好，相亲 17 次全黄了。
[近景] 我一问才知道，她每次都被安排去见“年薪 50 万的”，见完就自卑。
[出镜] 问题不在她，在介绍人根本没做匹配。
[字幕+主页] 郑州的，主页有我们这周的活动，自己看。
```

要点：每句不超过 20 字；第 4 句必须给判断，不能只讲故事；最后一句给动作但不留联系方式。

### 2. 街采/实拍（3-5 个回答剪成一条）

- 固定提问只问一个开放式问题，例如“你在郑州相亲遇到过最离谱的事是什么？”
- 剪辑节奏：一个问题 → 3 个不同回答 → 一句总结判断
- 出镜者必须口头同意出镜；不同意的打码或剪掉

### 3. 图文 plog（3-9 图）

| 图位 | 内容 |
| --- | --- |
| 头图 | 身份标识（工牌/话筒标/现场）+ 核心信息大字 |
| 2-4 图 | 场景实拍、资料墙、活动现场 |
| 5-8 图 | 信息图：本地单身画像、避坑清单 |
| 尾图 | 一句引导：“郑州的，主页看这周安排” |

正文 100-200 字，短句分行，不复述图片内容。

### 4. 水号大字报（纯文字，快产快发）

一张纯色底 + 3-5 行大字，观点要锐但不冒犯：
- 可用：“郑州相亲市场，男的真比女的急？”
- 禁用：任何针对性别、地域、职业群体的贬损判断

### 5. 评论区置顶回复

结构：接情绪 → 给具体信息 → 引导看主页。示例见 `content-playbook.md` 第六节。

### 6. 私信首句（每天总额 2-3 条，不可批量）

```
看到你在评论区问郑州相亲的事——我们这周有个小局，主页有详情，你自己看下合不合适。
```
只说一次，不追问、不留号、不催单。

## 三、语言规范

1. 一句话一个意思，口播句不超过 20 字。
2. 禁用黑话：赋能、闭环、抓手、颗粒度、打法、心智。
3. 禁用爹味句式：“你应该”“你必须”“现在年轻人就是”。
4. 数字要具体可核：不说“很多人”，说“我问了 30 个人，21 个”。
5. 结尾给动作，不给联系方式。

## 四、交付时的输出格式

```
【合规结论】绿灯 / 黄灯（附需改 2 处）/ 红灯
【标题备选】1. … 2. … 3. …
【前三秒】…（提问式）
【口播稿】
[画面] 文案
[画面] 文案
【封面】画面：… 大字：…
【话题】#郑州相亲 #体制内单身 #金水区
【合规细节】第 3 句原表述有绝对化用语，已改为 …
```

黄灯和红灯时，**必须同时给改好的版本**，不能只报问题让用户自己改。
